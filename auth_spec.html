Auth Service

Спецификация взаимодействия микросервиса аутентификации, регистрации и сессий.

Базовый адрес API
http://localhost:8001
Swagger UI документация
http://localhost:8001/docs
Схема авторизации
Bearer JWT Token
Срок действия JWT-токена
60 минут (1 час)

Правила безопасности и валидации:

Заголовок авторизации Authorization: Bearer <access_token> требуется передавать для защищённых методов.

Срок действия JWT-токена составляет 60 минут (1 час) с момента успешной авторизации.

Требования к логину: длина от 3 до 64 символов, требуется не менее 3 букв.

Требования к паролю: длина от 6 до 128 символов, требуется хотя бы 1 заглавная буква и 1 цифра.

Ограничение частоты запросов: не более 10 запросов за 60 секунд для эндпоинтов регистрации и входа. При превышении возвращается код 429 Too Many Requests с заголовком Retry-After.

Эндпоинт GET / выполняет автоматический редирект (HTTP 307) на страницу документации Swagger /docs.

Лимит: 10 за 60 сек

Регистрация нового пользователя.

Создаёт учётную запись пользователя. Пароль хэшируется с солью. Действует ограничение частоты: максимум 10 запросов в минуту с одного IP-адреса.

Параметры тела запроса (JSON)
ПолеТипОбязательностьТребования
loginstringОбязательноДлина от 3 до 64 символов, не менее 3 букв, уникален
passwordstringОбязательноДлина от 6 до 128 символов, хотя бы 1 заглавная буква и 1 цифра
emailstringОбязательноФормат электронной почты, уникален
Тело запроса регистрации
{
  "login": "SashaGrey",
  "password": "P@ssw0rd",
  "email": "murrr@gmail.com"
}
Возможные HTTP-коды и ответы
201 Created Пользователь успешно зарегистрирован 
{
  "id": 1,
  "login": "SashaGrey",
  "email": "murrr@gmail.com"
}
409 Conflict Логин или email уже заняты
Если логин уже зарегистрирован:
{
  "detail": "Пользователь с таким логином уже существует"
}
Если email уже зарегистрирован:
{
  "detail": "Пользователь с таким email уже существует"
}

Лимит: 10 за 60 сек

Проверяет логин и пароль. При совпадении выпускает подписанный JWT-токен со сроком жизни 60 минут (1 час). Токен требуется передавать в заголовке Authorization: Bearer <токен>.

GET /auth/me

Получить текущего авторизованного пользователя.

Требуется передать заголовок Authorization: Bearer <access_token>. Возвращает идентификатор, логин и email пользователя.

Возможные HTTP-коды и ответы
200 OK Данные текущего пользователя 
{
  "id": 1,
  "login": "SashaGrey",
  "email": "murrr@gmail.com"
}
401 Unauthorized Ошибки авторизации
Если заголовок Authorization не был передан:
{
  "detail": "Not authenticated"
}
Если токен просрочен (прошло более 60 минут) или подделан:
{
  "detail": "Недействительный или истёкший токен"
}
Если пользователь ранее совершил выход с данным токеном:
{
  "detail": "Токен был отозван. Нужен повторный вход."
}
POST /auth/logout
Bearer Auth

Выход из системы и отзыв текущего токена.

Вносит идентификатор текущего токена (jti) в список отозванных токенов. После этого данный токен отклоняется сервисом.

Возможные HTTP-коды и ответы
200 OK Токен успешно отозван 
{
  "message": "Успешный выход из системы. Токен отозван."
}
401 Unauthorized Токен не передан или недействителен 
{
  "detail": "Недействительный токен"
}
