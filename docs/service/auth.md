# Микросервис Auth (Аутентификация и пользователи)

## 1. Где находится

- **Каталог:** `pyth/auth`
- **Основной файл запуска:** `pyth/auth/main.py`
- **Конфигурация:** `pyth/auth/config.py`
- **Порт сервиса:** `8001` (внутри контейнера `8000`)
- **Базовый URL:** `http://localhost:8001`
- **Документация Swagger:** `http://localhost:8001/docs`

---

## 2. Что делает

Микросервис Auth отвечает за управление учетными записями пользователей и безопасность системы:
- Регистрация новых пользователей с проверкой формата email и надежности пароля.
- Аутентификация по логину и паролю.
- Выпуск токенов доступа JWT (JSON Web Token).
- Предоставление данных профиля текущего авторизованного пользователя (`/auth/me`).
- Выход из системы (Logout) с отзывом и аннулированием токена через черный список.
- Защита от подбора паролей и спам-запросов с помощью встроенного ограничителя частоты (Rate Limiter).

---

## 3. Особенности

### Как работает
- **Хеширование паролей:** Пароли не хранятся в открытом виде. Для хеширования используется алгоритм `bcrypt` с динамической солью (`auth/security.py`).
- **Формирование токена JWT:** При успешной проверке пароля сервис выпускает токен по алгоритму `HS256`. В полезную нагрузку (payload) токена записываются:
  - `sub`: идентификатор пользователя (`user_id`).
  - `jti`: уникальный идентификатор токена (UUID4).
  - `iat`: время выпуска токена.
  - `exp`: время истечения срока действия (по умолчанию 60 минут).
- **Отзыв токенов при выходе (Logout):** При вызове эндпоинта `/auth/logout` идентификатор `jti` токена заносится в таблицу `revoked_tokens`. При каждом обращении к закрытым эндпоинтам сервис проверяет, нет ли токена в этой таблице.
- **Ограничение частоты запросов (Rate Limiter):** В модуле `auth/lim.py` реализован механизм, который отслеживает число запросов с IP-адреса клиента. На эндпоинты регистрации и авторизации установлено ограничение (не более 10 запросов в минуту). При превышении возвращается статус `429 Too Many Requests` с заголовком `Retry-After`.
- **Локализация ошибок:** В `auth/main.py` встроен обработчик ошибок валидации, переводящий системные сообщения Pydantic на русский язык.

### С чем взаимодействует
- **База данных:** Таблица `auth` (пользователи) и таблица `revoked_tokens` (черный список токенов). В Docker используется PostgreSQL, при запуске без Docker — локальный файл SQLite `tether.db`.
- **Микросервис Diary:** Сервис Diary использует тот же секретный ключ `JWT_SECRET_KEY` для проверки токенов, выданных сервисом Auth, что обеспечивает сквозную авторизацию без лишних межсервисных сетевых запросов.

### Подробнее про эндпоинты

| Метод | Путь | Описание | Параметры и тело | Защита |
| :--- | :--- | :--- | :--- | :--- |
| `POST` | `/auth/register` | Регистрация нового пользователя | JSON: `login` (3-64 симв.), `email`, `password` (6-128 симв.) | Rate Limiter |
| `POST` | `/auth/login` | Вход и получение токена | JSON: `login`, `password` | Rate Limiter |
| `GET` | `/auth/me` | Получение профиля текущего пользователя | Возвращает: `id`, `login`, `email`, `created_at` | Bearer JWT |
| `POST` | `/auth/logout` | Выход из системы с отзывом токена | Добавляет `jti` токена в черный список | Bearer JWT |
| `GET` | `/health` | Проверка доступности сервиса | Возвращает: `{"status": "ok", "service": "auth"}` | Открытый |
| `GET` | `/` | Редирект на Swagger | Перенаправляет на `/docs` (HTTP 307) | Открытый |

## 4. Детальное описание файлов исходного кода (.py)

### `main.py`
Точка входа приложения FastAPI:
- Функция `longlive(_: FastAPI)`: асинхронный lifespan-контекст, выполняющий создание таблиц в базе данных (`Base.metadata.create_all(bind=engine)`) перед приемом сетевых запросов.
- Инициализация `app = FastAPI(...)` с русскоязычным описанием метаданных и OpenAPI-спецификации.
- Подключение `CORSMiddleware`: настроены заголовки `allow_origin_regex=r".*"`, `allow_credentials=True`, `allow_methods=["*"]`, `allow_headers=["*"]`.
- `validation_exception_handler(request, exc)`: перехватывает исключения `RequestValidationError` и переводит типовые ошибки валидации Pydantic (неверный формат email, превышение длины строки, обязательность поля) в понятные русскоязычные сообщения.
- Подключение роутов через `app.include_router(router)`.

### `models.py`
ORM-модели базы данных на SQLAlchemy 2.0 с типизированными `Mapped`-атрибутами:
- **Класс `usr` (таблица `auth`):**
  - `id`: первичный ключ (`Integer`, `primary_key=True`);
  - `login`: логин пользователя (`String(64)`, уникальный, индексированный);
  - `password_hash`: хеш пароля (`String(255)`);
  - `email`: электронная почта (`String(320)`, уникальный, индексированный);
  - `created_at`: дата и время регистрации с поддержкой таймзоны (`server_default=func.now()`).
- **Класс `badtok` (таблица `revoked_tokens`):**
  - `id`: первичный ключ;
  - `jti`: уникальный идентификатор отозванного токена (`String(64)`, уникальный, индексированный);
  - `user_id`: идентификатор пользователя (`Integer`, индексированный);
  - `expires_at`: исходное время экспирации токена (`DateTime(timezone=True)`);
  - `revoked_at`: точное время аннулирования (`server_default=func.now()`).

### `routes.py`
Маршруты API и внедрение зависимостей:
- `bearer_scheme = HTTPBearer(...)`: извлечение токена из заголовка `Authorization: Bearer <токен>`.
- `authlim = limiter(limit=10, window=60)`: инстанс Rate Limiter с лимитом 10 запросов в минуту.
- `getactualuser(cred, db)`: функция зависимости (dependency). Извлекает учетные данные пользователя через `authserv.getuser()`, проверяет отсутствие отзыва токена, при отсутствии токена возвращает статус `401 Unauthorized`.
- Обработчики эндпоинтов:
  - `reg(...)`: маршрут `POST /auth/register`;
  - `login(...)`: маршрут `POST /auth/login`;
  - `me(...)`: маршрут `GET /auth/me`;
  - `logout(...)`: маршрут `POST /auth/logout`;
  - `health()`: маршрут `GET /health`;
  - `to_docs()`: маршрут `GET /`.

### `schemas.py`
Модели валидации Pydantic:
- `useradd`: валидация регистрации. Проверяет `login` (длина от 3 до 64 символов), валидный `email` через тип `EmailStr`, пароль `password` (длина от 6 до 128 символов).
- `loginreq`: модель входа с полями `login` и `password`.
- `tokenresp`: схема ответа с полями `access_token`, `token_type` (константа `"bearer"`) и `expires_in` (в секундах).
- `useresp`: схема публичного представления профиля пользователя (`id`, `login`, `email`, `created_at`).
- `msgresp`: схема ответа с текстовым сообщением `message`.

### `service.py`
Слой бизнес-логики (класс `authserv`):
- `authserv.reg(db, data)`: проверяет отсутствие пользователя с таким же логином или email (выбрасывает `409 Conflict`), хеширует пароль через `hashpass()`, создает и сохраняет объект `usr` в БД.
- `authserv.auth(db, data)`: ищет пользователя по логину, проверяет хеш пароля через `verpass()`, при несовпадении выбрасывает `401 Unauthorized`. При успехе генерирует токен через `createtokenaccess()` и возвращает объект `tokenresp`.
- `authserv.getuser(db, tok)`: декодирует JWT токен через `decodetoken()`, проверяет наличие `jti` в таблице `badtok` (если токен отозван — выбрасывает `401 Unauthorized`), находит пользователя по ID (`sub`) и возвращает объект `usr`.
- `authserv.logout(db, tok)`: декодирует токен, сохраняет запись с его `jti`, `user_id` и `expires_at` в таблицу `badtok` для мгновенной инвалидации.

### `security.py`
Функции криптографии и безопасности:
- `hashpass(password: str) -> str`: генерирует соль `bcrypt.gensalt()` и хеширует пароль.
- `verpass(plain: str, hashed: str) -> bool`: сверяет открытый пароль с хешем через `bcrypt.checkpw()`.
- `createtokenaccess(user_id: int) -> str`: формирует полезную нагрузку (`sub`, `jti`, `iat`, `exp`), подписывает токен секретным ключом `jwt_secret_key` с алгоритмом `HS256`.
- `decodetoken(tok: str) -> dict`: валидирует подпись и декодирует payload токена с помощью библиотеки `PyJWT`.

### `lim.py`
Ограничитель частоты запросов (In-memory Rate Limiter):
- Класс `limiter` (также доступен как `RateLimiter`):
  - Хранит историю вызовов по IP-адресам: `history: dict[str, list[float]]`.
  - Метод `__call__(req: Request)`: определяет IP клиента (`req.client.host`), очищает устаревшие временные метки за пределами скользящего окна (`window`), проверяет текущее число запросов.
  - При превышении лимита рассчитывает секунды до разблокировки (`retry`) и генерирует исключение `HTTPException(status_code=429)` с заголовком `Retry-After`.

### `config.py`
Конфигурация сервиса на базе `pydantic-settings`:
- Класс `Config(BaseSettings)`: считывает переменные окружения `DATABASE_URL`, `JWT_SECRET_KEY`, `JWT_ALGORITHM`, `JWT_ACCESS_TOKEN_EXPIRE_MINUTES`.
- Функция `getcfg()`: возвращает синглтон-экземпляр настроек с кешированием `@lru_cache`.

### `database.py`
Подключение к реляционной базе данных:
- `create_engine(..., pool_pre_ping=True)`: пул соединений с проверкой живости подключения.
- `SessionLocal = sessionmaker(...)`: фабрика локальных сессий SQLAlchemy.
- `Base(DeclarativeBase)`: базовый класс для ORM-моделей.
- Генератор `getdb()`: контекстный генератор сессий для FastAPI dependency injection с гарантированным закрытием соединения в блоке `finally`.

### `testuser.py`
Скрипт первичной подготовки тестовой учетной записи:
- Функция `mktestuser()`: создает таблицы БД, ищет пользователя с логином `tester`, при его отсутствии создает аккаунт `tester` / `tester` (`tester@tester.test`), выпускает готовый токен доступа и выводит учетные данные в консоль.
