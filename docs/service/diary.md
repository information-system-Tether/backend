# Микросервис Diary (Дневник питания и расчет КБЖУ)

## 1. Где находится

- **Каталог:** `pyth/diary`
- **Основной файл запуска:** `pyth/diary/main.py`
- **Конфигурация:** `pyth/diary/config.py`
- **Порт сервиса:** `8002` (внутри контейнера `8000`)
- **Базовый URL:** `http://localhost:8002`
- **Документация Swagger:** `http://localhost:8002/docs`

---

## 2. Что делает

Микросервис Diary является центральным компонентом бизнес-логики системы:
- Ведение суточных листов питания (`diary_sheets`) с фиксацией веса тела по датам.
- Учет съеденных блюд и продуктов (`entries`) с пересчетом калорий, белков, жиров, углеводов и воды под вес порции.
- Профиль здоровья пользователя (`bio`) с расчетом суточных норм калорий (коридор min/max), белков, жиров, углеводов, воды и шагов.
- Каталог базовых справочных продуктов (`base_products`) с пищевой ценностью на 100 грамм.
- Создание и редактирование собственных пользовательских продуктов (`user_products`).
- Управление списком избранных продуктов (`favorites`).
- Предоставление статистики и аналитики за неделю и за все время.
- Полная выгрузка данных пользователя для синхронизации с клиентом.

---

## 3. Особенности

### Как работает
- **Сквозная проверка токена JWT:** Сервис Diary не обращается по сети в сервис Auth для проверки токена. В модуле `diary/security.py` входящий Bearer-токен расшифровывается локально с использованием общего секретного ключа `JWT_SECRET_KEY`, после чего из поля `sub` извлекается `user_id`.
- **Математический модуль расчета норм (`diary/calculation.py`):**
  - Расчет базового метаболизма (BMR) по формулам Миффлина — Сан Жеора и Харриса — Бенедикта на основе пола, возраста, роста и веса.
  - Расчет общего суточного расхода калорий (TDEE) с учетом коэффициента активности (от 1.2 до 1.9 для 5 уровней активности).
  - Расчет калорий под выбранную цель (снижение веса с дефицитом, поддержание, набор массы с профицитом).
  - Расчет граммов макронутриентов: белки (1.5-2.2 г на кг веса), жиры (0.8-1.0 г на кг веса), углеводы (остаток энергии), норма воды (30-35 мл на кг) и целевые шаги.
- **Пересчет граммовок порций:** При добавлении продукта в лист указывается количество граммов (`quantity_grams`). Сервис автоматически пересчитывает пищевую ценность: `калории = калории_на_100г * (quantity_grams / 100)`.
- **Идемпотентность:** Поддерживается ключ `idempotency_key` при создании продуктов для предотвращения случайного дублирования записей при повторной отправке запроса с клиента.
- **Автоматическая миграция схемы (`diary/database.py`):** Функция `addcols()` проверяет структуру таблиц базы данных при старте и автоматически выполняет `ALTER TABLE` для добавления недостающих колонок без использования сторонних инструментов миграций.
- **Начальное сидирование каталога:** При первом старте модуль `diary/baseproducts.py` автоматически наполняет таблицу базовых продуктов справочными позициями с проверенным КБЖУ.

### С чем взаимодействует
- **Микросервис Auth:** Принимает и валидирует токены JWT, выпущенные сервисом Auth.
- **База данных:** Таблицы `diary_sheets`, `entries`, `bio`, `base_products`, `user_products`, `favorites`. В Docker используется PostgreSQL, при локальном запуске — SQLite (`tether.db`).

## 4. Детальное описание файлов исходного кода (.py)

### `main.py`
Точка входа микросервиса дневника:
- Асинхронный lifespan `longlive(_: FastAPI)`: при старте приложения создает таблицы в БД (`Base.metadata.create_all`), выполняет мягкую миграцию недостающих полей через `addcols()` и загружает базовые продукты через `seedbase(db)`.
- Инициализация `FastAPI` с настройками OpenAPI и версией 2.2.
- Настройка `CORSMiddleware` для взаимодействия с фронтендом и мобильными клиентами.
- `validation_exception_handler`: расширенная русификация ошибок валидации Pydantic для числовых полей, границ диапазонов (`gt`, `ge`, `le`), форматов дат и граммовок.
- Регистрация маршрутизатора `app.include_router(router)`.

### `calculation.py`
Математическое ядро расчета метаболизма и пищевых норм:
- `calc_bmr(gender, weight, height, age)`: расчет базового метаболизма. Для мужчин: `10 * weight + 6.25 * height - 5 * age + 5`, для женщин: `10 * weight + 6.25 * height - 5 * age - 161`.
- `calc_tdee(bmr, activity_level)`: умножение BMR на коэффициент активности (1: 1.2 — сидячий; 2: 1.375 — легкая; 3: 1.55 — умеренная; 4: 1.725 — высокая; 5: 1.9 — экстремальная).
- `calc_target_calories(tdee, target_goal)`: вычисление целевого коридора калорий (1: похудение дефицит 15-20%; 2: поддержание формы; 3: набор массы профицит 10-15%; 4: интенсивное снижение).
- `calc_macros(calories, weight, target_goal)`: расчет белков (1.5–2.2 г/кг), жиров (0.8–1.0 г/кг), углеводов (вычисляются по формуле `(calories - proteins*4 - fats*9) / 4`).
- `calc_water(weight)`: расчет суточной нормы воды из расчета 30–35 мл на килограмм веса.
- `calc_steps(activity_level)`: целевое количество шагов в день (от 6000 до 15000 шагов).

### `models.py`
ORM-модели базы данных на SQLAlchemy 2.0:
- **`diarylist` (таблица `diary_sheets`):**
  - `id`: первичный ключ;
  - `user_id`: идентификатор владельца (индексирован);
  - `sheet_date`: дата листа (`Date`, индексирована);
  - `weight`: зафиксированный вес тела на эту дату (`Numeric(6, 2)`, опционально);
  - `created_at`: дата создания;
  - `entries`: связь с записями `entry` с каскадным удалением (`cascade="all, delete-orphan"`).
  - Уникальный составной индекс `UniqueConstraint("user_id", "date")`.
- **`entry` (таблица `entries`):**
  - `id`: первичный ключ;
  - `sheet_id`: внешний ключ на `diary_sheets.id`;
  - `title`: название блюда/продукта;
  - `calories`, `proteins`, `fats`, `carbs`, `water`: рассчитанная пищевая ценность съеденной порции;
  - `product_type`: категория продукта;
  - `base_product_id` / `user_product_id`: ссылка на исходный продукт из каталога;
  - `quantity_grams`: масса порции в граммах.
- **`bio` (таблица `bio`):**
  - Профиль здоровья пользователя: `user_id` (уникальный), `gender` ('m'/'f'), `age`, `weight`, `height`, `target_goal` (1-4), `activity_level` (1-5), рассчитанные нормы `min_target_calories`, `max_target_calories`, `target_proteins`, `target_fats`, `target_carbs`, `target_water`, `target_steps`.
- **`baseprod` (таблица `base_products`):**
  - Справочник системных продуктов: `name` (уникальный), `description`, `product_type`, `calories`, `proteins`, `fats`, `carbs` на 100 г, `idempotency_key`.
- **`userprod` (таблица `user_products`):**
  - Персональные продукты пользователя: `user_id`, `name`, `description`, `product_type`, `calories`, `proteins`, `fats`, `carbs` на 100 г.
- **`fav` (таблица `favorites`):**
  - Избранные продукты пользователя с внешними ссылками на `base_product_id` или `user_product_id`.

### `routes.py`
Контроллеры API:
- Внедрение зависимостей: `getactualuid` (извлечение `user_id` из JWT токена), `getdb` (сессия БД).
- Обработчики профиля здоровья: `getheal`, `createheal`, `updateheal`, `delheal`.
- Обработчики листов: `getsheet`, `createsheet`, `updatesheet`, `delsheet`.
- Обработчики записей дневника: `addentry`, `updateentry`, `delentry`.
- Обработчики каталогов продуктов: `listbaseprod`, `syncbaseprod`, `listmyprod`, `addmyprod`, `updatemyprod`, `delmyprod`.
- Обработчики избранного: `listfav`, `addfav`, `delfav`.
- Обработчики аналитики: `getweeklystats`, `getsummarystats`, `getadvice`, `syncall`.

### `services.py`
Слой бизнес-логики:
- Класс `healserv`: создание, обновление и расчет профиля `bio`, синхронизация с калькулятором `calculation.py`.
- Класс `diarieserv`: поиск листа по дате, агрегация и суммирование калорий и БЖУ по всем приемам пищи за день, добавление записи с пересчетом граммовок, каскадное удаление.
- Класс `prodserv`: управление базовыми продуктами, создание пользовательских продуктов с контролем уникальности и идемпотентности, управление избранным.
- Класс `statsserv`: расчет недельной динамики калорийности, сопоставление с целевым коридором, формирование советов по оптимизации рациона.

### `schemas.py`
Схемы данных Pydantic v2:
- Схемы профиля: `healcreate`, `healupd`, `healresp` с валидацией границ веса (20–400 кг), роста (0.5–2.5 м), возраста (10–120 лет).
- Схемы листов и записей: `sheetresp`, `entryadd`, `entryupd`, `entryresp` с валидацией строго положительного веса порции (`quantity_grams > 0`).
- Схемы продуктов: `prodadd`, `produpd`, `prodresp`.
- Схемы избранного: `favadd`, `favresp`.
- Схемы аналитики: `WeeklyStatsResponse`, `SummaryStatsResponse`, `RecommendationsResponse`.

### `security.py`
Безопасность и разграничение доступа:
- `getactualuid(cred)`: извлекает и верифицирует Bearer JWT токен с помощью общего ключа `jwt_secret_key`, парсит поле `sub` как целочисленный `user_id`. При любой ошибке подписи или срока действия генерирует исключение `401 Unauthorized`.
- `veradm(key)`: проверяет соответствие значения HTTP-заголовка `X-Admin-Key` системному ключу администратора `admin_api_key`.

### `database.py`
Слой подключения к БД и автомиграции:
- Инициализация `engine` и `SessionLocal`.
- Генератор зависимости `getdb()`.
- Функция `addcols()`: через SQLAlchemy `inspect` анализирует существующие колонки таблиц и при их отсутствии автоматически выполняет прямые команды `ALTER TABLE ADD COLUMN`, исключая необходимость применения сторонних миграторов для базовых изменений схемы.

### `baseproducts.py`
Справочник продуктов по умолчанию:
- Обширный датасет со справочными позициями типовых продуктов (мясо, птица, рыба, крупы, бобовые, овощи, фрукты, молочная продукция, масла, орехи).
- Функция `seedbase(db)`: проверяет наличие записей в `base_products` и осуществляет пакетную вставку при первом запуске.

### `config.py`
Настройки сервиса:
- Класс `Config(BaseSettings)` с параметрами `database_url`, `jwt_secret_key`, `jwt_algorithm`, `admin_api_key`.
- Кешированная функция доступа `getcfg()`.

### `init_db.py`
Автономный скрипт инициализации:
- Создает все таблицы микросервиса дневника и вызывает `seedbase(db)` для наполнения базы продуктов.
