## 2. Что делает

Микросервис KB (Knowledge Base) предоставляет пользователям справочные материалы, ответы на часто задаваемые вопросы (FAQ) и экспертные рекомендации по питанию:
- Хранение статей и ответов по темам: дефицит и профицит калорий, макронутриенты, водный баланс, диеты и стандарты питания.
- Полнотекстовый поиск по ключевым словам.
- Группировка статей по тематическим блокам и категориям.
- Постраничная выдача (пагинация) в заголовках ответа и в формате JSON.
- Административный интерфейс для создания, изменения и удаления статей.

## 3. Особенности

### Как работает
- **Полнотекстовый поиск по словам (AND-логика):** В модуле `kb/services.py` поисковый запрос разбивается на отдельные слова. Поиск устроен так, что статья попадает в результат только в том случае, если каждое введенное слово найдено хотя бы в одном из полей: `question` (вопрос), `answer` (ответ), `tags` (теги) или `block` (тематический блок).
- **Два формата пагинации:**
  - `GET /kb`: возвращает массив статей, а параметры пагинации передает в стандартных HTTP-заголовках ответа: `X-Total-Count`, `X-Page`, `X-Page-Size`, `X-Total-Pages`, `X-Has-Next`, `X-Has-Prev`. Поддерживает управление как через `page`/`page_size`, так и через `limit`/`offset`.
  - `GET /kb/paginated`: возвращает единый JSON-объект, содержащий массив `items` и метаданные пагинации внутри тела ответа. Это удобно для клиентов, которым предпочтительнее парсить тело ответа без чтения заголовков.
- **Защита административных действий:** Операции добавления, изменения и удаления статей закрыты проверкой секретного административного ключа `ADMIN_API_KEY` (передается в HTTP-заголовке `X-Admin-Key`). Проверка выполняется в модуле `kb/security.py`.
- **Автоматическое наполнение базы (сидирование):** При старте сервиса модуль `kb/seed_kb.py` проверяет наличие статей и автоматически загружает начальный пул из 113 экспертных материалов. Полный перечень всех вопросов приведен в [**docs/rosterofquestions.md**](file:///D:/Tether/docs/rosterofquestions.md).
- **Оптимизация Docker-образа:** Файл `kb/Dockerfile` наследует базовый слой от `tether-diary`, что ускоряет сборку и экономит дисковое пространство.

### С чем взаимодействует
- **База данных:** Таблица `kb_articles`. В Docker используется PostgreSQL, при локальном запуске — SQLite (`tether.db`).
- **Автономность:** Для чтения статей и поиска сервис не требует авторизации пользователя и работает полностью независимо.

## 4. Детальное описание файлов исходного кода (.py)

### `main.py`
Точка входа микросервиса базы знаний:
- Асинхронный lifespan `longlive(_: FastAPI)`: создает таблицы в БД через `Base.metadata.create_all(bind=engine)` и выполняет сидирование статей из `seed_kb.py` через `seedkb(db)`.
- Инициализация `FastAPI` с параметрами OpenAPI: `title="Tether Knowledge Base"`, `version="1.0"`.
- Настройка `CORSMiddleware` с параметром `expose_headers`: в клиентское приложение явно пробрасываются специальные заголовки пагинации:
  - `X-Total-Count`, `X-Page`, `X-Page-Size`, `X-Total-Pages`, `X-Has-Next`, `X-Has-Prev`.
- `validation_exception_handler`: русскоязычный обработчик ошибок Pydantic для длины строк и обязательных полей.
- Подключение роутера `app.include_router(router)`.

### `models.py`
ORM-модель базы данных:
- **Класс `kbarticle` (таблица `kb_articles`):**
  - `id`: первичный ключ (`Integer`, `primary_key=True`);
  - `question`: формулировка вопроса или темы статьи (`Text`);
  - `answer`: подробный структурированный текст ответа (`Text`);
  - `category`: категория статьи (`String(64)`, индексирована, по умолчанию `"general"`);
  - `block`: название тематического блока для навигационного меню (`String(128)`, индексировано, опционально);
  - `tags`: ключевые слова через запятую (`String(512)`, опционально);
  - `created_at`: дата и время создания с таймзоной (`DateTime(timezone=True)`, `server_default=func.now()`).

### `routes.py`
Контроллеры и логика маршрутизации:
- Вспомогательная функция `_resolve_pagination(page, page_size, limit, offset)`: приводит оба формата пагинации (`page/page_size` и `limit/offset`) к единым значениям `offset` и `limit`.
- Вспомогательная функция `_set_pagination_headers(response, total, calc_offset, calc_limit, eff_size, items_count)`: рассчитывает текущую страницу, общее число страниц, флаги наличия следующей/предыдущей страницы (`has_next`, `has_prev`) и записывает их в HTTP-заголовки ответа.
- Эндпоинты:
  - `listarticles(...)`: `GET /kb` — выборка статей с фильтрацией по категории, блоку, поисковому запросу и метаданными в заголовках.
  - `listarticles_paginated(...)`: `GET /kb/paginated` — выборка статей с метаданными пагинации внутри тела JSON.
  - `listblocks(...)`: `GET /kb/blocks` — список уникальных тематических блоков.
  - `search(...)`: `GET /kb/search` — полнотекстовый поиск по ключевым словам.
  - `getarticle(...)`: `GET /kb/{aid}` — выдача статьи по ID.
  - `createarticle(...)`: `POST /kb` — добавление новой статьи (требует `X-Admin-Key`).
  - `updatearticle(...)`: `PUT /kb/{aid}` и `PATCH /kb/{aid}` — обновление статьи (требует `X-Admin-Key`).
  - `deletearticle(...)`: `DELETE /kb/{aid}` — удаление статьи (требует `X-Admin-Key`).

### `services.py`
Бизнес-логика базы знаний (класс `kbserv`):
- `kbserv.listarticles(db, category, block, q, offset, limit)`: формирует запрос к `kb_articles` с динамическими фильтрами по `category` и `block`. Если передан параметр `q`, вызывает внутреннюю логику полнотекстовой фильтрации. Возвращает кортеж `(список статей, общее количество)`.
- `kbserv.search(db, q, category, block, offset, limit)`: разбивает поисковую фразу `q` на отдельные токены (слова). Для каждого токена формирует условие: слово должно присутствовать либо в `question`, либо в `answer`, либо в `tags`, либо в `block` (поиск без учета регистра). Объединяет условия по оператору `AND`.
- `kbserv.listblocks(db)`: выполняет запрос `SELECT DISTINCT block FROM kb_articles WHERE block IS NOT NULL` и возвращает отсортированный список категорий.
- `kbserv.getarticle(db, aid)`: находит статью по ID, при отсутствии генерирует `404 Not Found`.
- `kbserv.create(db, data)`, `kbserv.update(db, aid, data)`, `kbserv.delete(db, aid)`: стандартные CRUD-операции.

### `seed_kb.py`
Справочный массив данных и функция сидирования:
- Массив `seed_articles`: содержит 113 готовых экспертных статей по 6 тематическим блокам:
  1. Стандарты, маркировка и законы.
  2. Методы взвешивания, расчёта и учёта.
  3. Нутриенты, витамины и макроэлементы.
  4. Калории, энергетический баланс и метаболизм.
  5. Гидратация и питьевой режим.
  6. Общие вопросы питания, физиологии и психологии.
- Функция `seedkb(db: Session)`: проверяет наличие записей в базе данных и при необходимости выполняет пакетное наполнение, выводя в лог число добавленных позиций.
- Полный структурированный реестр всех 113 вопросов доступен в документе [**docs/rosterofquestions.md**](file:///D:/Tether/docs/rosterofquestions.md).

### `schemas.py`
Схемы валидации Pydantic:
- `kbcreate`: схема создания статьи с валидацией минимальной длины вопроса (не менее 3 символов) и ответа.
- `kbupd`: схема обновления статьи с опциональными полями.
- `kbresp`: схема ответа с полной информацией о статье (`id`, `question`, `answer`, `category`, `block`, `tags`, `created_at`).
- `kbpaginated`: схема структурированного ответа с полями `items`, `total`, `page`, `page_size`, `total_pages`, `has_next`, `has_prev`.

### `security.py`
Безопасность административных операций:
- Функция `veradm(key: str = Header(..., alias="X-Admin-Key")) -> str`: проверяет соответствие ключа заголовка `X-Admin-Key` системному ключу `admin_api_key`. При несовпадении генерирует исключение `HTTPException(status_code=403, detail="Доступ запрещен: неверный административный ключ")`.

### `config.py`
Настройки сервиса:
- Класс `Config(BaseSettings)` с параметрами `database_url`, `admin_api_key`.
- Функция `getcfg()`.

### `database.py`
Подключение к СУБД:
- Создание SQLAlchemy `engine`, фабрики `SessionLocal` и генератора `getdb()`.

### `init_db.py`
Скрипт первичной инициализации:
- Создает таблицы базы знаний и запускает функцию `seedkb(db)`.

### `__init__.py`
Маркер пакета Python.
